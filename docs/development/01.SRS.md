## 1. 목적 및 배경

### 1.1 시스템 목적
**Dream Milestone 코칭 포털**은 삼성코칭동호회(SCC) 소속 코치가 대학생·대학원생 멘티를 대상으로 5회기 다회기 커리어 코칭을 수행할 때 사용하는 **반응형 웹 기반 코칭 가이드북 및 운영 툴킷 시스템**이다.

### 1.2 해결하려는 문제
1. **분산된 코칭 자료**: PDF 가이드북, 사전 질문지, 회기별 워크시트, 코칭일지 링크, 성과평가 링크가 파편화되어 코칭 현장에서 즉각 참조하기 어렵다.
2. **다회기 운영 자신감 편차**: 대학생·대학원생 대상 5회기 커리어 코칭의 회기별 시간 배분(60분 5단계), 핵심 발문, 공감 가이드, 경계 관리(`Coaching First` vs `Experience on Demand`)를 현장에서 일관되게 지원하는 디지털 도구가 필요하다.
3. **운영 및 인프라 비용 제약**: 동호회 운영 특성상 유료 DB나 서버 유지비 없이 무료 클라우드 티어(Netlify Free Tier + Google Forms + Google Drive)만으로 안정적으로 운영되어야 한다.

### 1.3 이해관계자 및 사용자 역할

| 역할 코드 | 역할명 | 주요 책임 및 시스템 사용 목적 |
| :--- | :--- | :--- |
| `ROLE-COACH` | **삼코동 코치 (주 사용자)** | 공용 비밀번호로 포털에 입장하여 프로그램 개요, 프리세션~5회기 단계별 가이드 열람, 체크포인트 점검, 코칭일지(1~4회기) 및 코치 성과평가(5회기) 작성, 학생에게 평가 링크 및 워크북 전달 |
| `ROLE-MENTEE` | **학생/멘티 (간접 사용자)** | 포털에 직접 로그인하지 않으며, 코치가 전달한 워크시트(Google Drive)와 5회기 학생 성과평가(Google Form) 링크를 통해 참여 |
| `ROLE-ADMIN` | **삼성코칭동호회(SCC) 운영진** | 공용 비밀번호(`COACH_SHARED_PASSWORD`), 구글폼 3종 URL, 구글드라이브 5종 공유 URL을 관리하고 Netlify 배포를 승인 |

## 2. 시스템 경계 및 범위 (Scope Boundary)

### 2.1 시스템 경계
- **In-Scope (시스템 내부)**:
  - 삼코동 브랜딩 랜딩 및 코치 공용 비밀번호 로그인/로그아웃 (`/login`, `POST /api/login`, `POST /api/logout`)
  - 보호 라우트 미들웨어(`middleware.ts`) 및 `HttpOnly` 서명 쿠키(`dm_session`) 검증
  - 3대 기능 탭 포털 웹앱 (`탭 1: 개요`, `탭 2: 코칭모델[프리세션 + 1~5회기 + Between Session]`, `탭 3: 참조자료`)
  - 브라우저 `localStorage` 기반 코치 체크포인트 상태 유지, 다크/라이트 테마 전환, 학생 성과평가 URL 클립보드 복사
- **External Dependencies (외부 연동 경계)**:
  - **Google Forms (3종)**: ① 1~4회기 통합 코칭일지 폼(회기 prefill), ② 5회기 코치 성과평가 폼, ③ 5회기 학생 성과평가 폼
  - **Google Drive (5종)**: Full Guide PDF, 프리세션 사전 준비지, 학생용 워크북, 코치 사전 OT 및 운영 매뉴얼, 핵심 질문 라이브러리 & 가치 카드
- **Explicit Exclusions (MVP 제외 범위)**:
  - 개별 코치/학생 회원가입 및 자체 RDBMS/NoSQL 데이터베이스 구축 제외
  - 포털 내부에서 학생 실명이나 코칭일지 본문을 직접 입력·저장하는 기능 제외(개인정보 보호를 위해 Google Forms로 일원화)

## 5. 비즈니스 규칙 (`RULE-*`)

| ID | 규칙명 | 규칙 정의 및 예외 처리 |
| :--- | :--- | :--- |
| `RULE-001` | 코치 전용 접근 제한 | 공용 비밀번호 인증을 통과한 세션(`dm_session`)만 포털 콘텐츠(`/overview`, `/model/*`, `/references`)를 열람할 수 있다. 쿠키 만료(기본 12시간) 시 `/login`으로 자동 이동한다. |
| `RULE-002` | 비식별 학생 코드 기록 원칙 | 포털 내 모든 코칭일지 안내 및 템플릿은 학생 실명·학번·연락처 입력을 금지하고 비식별 `학생 코드`만 기록하도록 명시한다. |
| `RULE-003` | SHARE 프로토콜 준수 | 코치의 실무 경험·정보 제공(`Experience on Demand`)이 포함되는 모든 회기 가이드(특히 2회기 심화 단계)에는 반드시 학생의 사전 동의 확인(`SHARE` 5단계) 체크포인트를 포함한다. |
| `RULE-004` | 회기별 외부 폼 매핑 규칙 | 1~4회기는 **코칭일지 구글폼**(회기 파라미터 `1회기`~`4회기`)만 노출하고, 5회기는 **코치 성과평가 구글폼**과 **학생 성과평가 구글폼**(열기+링크 복사) 2종을 노출한다. |
| `RULE-005` | 미확정 외부 링크 안전 처리 | 운영진이 환경변수에 실제 Google Form/Drive URL을 주입하기 전(또는 URL이 비어 있는 경우), 버튼 클릭 시 깨진 페이지로 이동하지 않고 `"운영진 링크 연결 준비 중입니다."` 안내 모달/토스트를 표시한다. |
| `RULE-006` | 디자인 토큰 강제 규칙 | 모든 UI 컴포넌트는 `DESIGN.md`에 정의된 CSS 변수(`--color-bg-base`, `--color-primary`, `--color-text-muted` 등)만 사용하며, 순색(Pure Red/Blue/Green)이나 임의 하드코딩 헥사코드를 금지한다. |
| `RULE-007` | 기관 표기 단일화 규칙 | 포털 화면, 메타태그, 푸터, 가이드 본문 어디에도 외부 협회 약칭이나 명칭을 표기하지 않으며 **삼성코칭동호회(SCC)**로 단일 표기한다(`DEC-008`). |
| `RULE-008` | 미실행 실험의 학습 데이터화 | Between Session 회고 가이드에서는 학생의 실험 미실행을 실패나 감점으로 처리하지 않고, 학생의 현실 여건·에너지 리듬을 파악하는 학습 질문으로 연결한다. |
